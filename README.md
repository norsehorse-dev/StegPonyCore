# StegPonyCore

The shared Rust core behind StegPony: hide an encrypted message or file inside an ordinary image, and get it back with a passphrase or an age key. Without the secret there is nothing to find: no header, no signature, no fixed layout.

Part of the Pony family of privacy tools by NorseHorse. The Android app, and later iOS and desktop, all use this core so that every platform writes and reads the same bytes.

## What it does today (Phase A)

- **Headerless envelope.** ChaCha20-Poly1305 under a key from Argon2id (passphrase) or X25519 (public key). Lengths are padded to a fixed bucket table and stored masked. See [FORMAT.md](FORMAT.md).
- **age keys.** An `age1...` recipient is a StegPony recipient and an `AGE-SECRET-KEY-1...` identity reveals. Ephemeral keys are Elligator 2 encoded with torsion-dirty points, so they look like random bytes too.
- **Decoy.** Every image has two slots. Hide a second payload under a second secret, or the second slot gets random filler, and nobody can tell which.
- **Lossless mode.** PNG covers (8-bit gray, RGB, RGBA) and JPEG covers converted to PNG. Content-adaptive costs (HILL) and syndrome-trellis codes keep changes few and in textured areas.

In progress (Phase B):

- **JPEG coefficient codec.** A pure-Rust reader and writer for a JPEG's quantized DCT coefficients (`stegpony_core::jpeg`): baseline, extended sequential and progressive Huffman files, any sampling factors, restart intervals. No pixels and no IDCT, so a cover's own compression is kept; an unchanged file writes back byte for byte, and new Huffman tables are built only when changed coefficients need symbols the old ones lack. Checked against libjpeg, libjpeg-turbo and mozjpeg.

Coming next: the JPEG native carrier (rest of Phase B), the Android app (Phase C), text modes (Phase D), and a mode that survives messenger recompression (Phase E).

## Command line

```
cargo build --release
./target/release/stegpony keygen -o me.txt
./target/release/stegpony hide -c photo.png -o out.png -m "meet at noon"
./target/release/stegpony reveal out.png
./target/release/stegpony hide -c photo.png -o out.png -f secret.age -r age1...
./target/release/stegpony reveal out.png -i me.txt
./target/release/stegpony capacity photo.png
```

Passphrases are prompted for, or read from `STEGPONY_PASSPHRASE` and `STEGPONY_DECOY_PASSPHRASE`. Add a decoy with `--decoy-message` or `--decoy-file`, under `--decoy-recipient` or the decoy passphrase.

## What it does not promise

Steganography lowers the odds of being noticed; it does not make hiding undetectable. A large payload in a small image, a cover that exists publicly elsewhere, or an adversary who already knows you use StegPony all weaken it. Anything that re-encodes the image (resizing, filters, most messengers' photo mode) destroys a Lossless payload. Send the file unchanged.

## Building and testing

```
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test --workspace
```

Test covers are synthetic and generated by `tools/make_fixtures.py`. The format test vectors in `crates/stegpony-core/tests/vectors/` are frozen and are also checked by an independent implementation written from FORMAT.md:

```
pip install argon2-cffi cryptography pillow
python3 tools/check_vectors.py
```

The JPEG codec is checked against libjpeg on a matrix of generated covers (plus any JPEGs you name) by:

```
pip install numpy pillow jpeglib
cargo build --release --example jpeg_tool
python3 tools/check_jpeg.py
```
